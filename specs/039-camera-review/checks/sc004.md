# SC-004 — the Camera page with a 15-shot film (2026-11-28)

Film: `cam-app` (copy of charisma-30-cam: 15 shots, 43 options with real ¼ stills, Camera approval removed). Run on the
studio's own server stack in local mode (the UI test harness: its own data folder and ports 18860–18869; the owner's
running app on :8790 was not touched), driven by a real browser (Playwright, 1280 px).

| Check | Result |
|---|---|
| Pick an option on all 15 shots ("Use this", a different option each) + Approve | **24 s** of page time (target ≤ 5 min for a person) |
| Choices written per shot id | 15/15 in `camera/options.json` with `source: user`; `shot_plan.<S>.camera` for 15/15 |
| Camera point after Approve | `approved (ui)`; the Voice gate no longer stops on Camera |
| Page errors | 0 |
| A note on S5, then what the revise job runs (`camera suggest --shots S5 --keep-others`, `camera stills --shots S5`) | S5 changed; **14/14 other shots byte-identical** (options + stills hashed) · stills 11 s |

Bugs found and fixed on the way:
- **Fast picking came back "conflict"**: the page polls and redrew S6 as chosen while its edit was still running, so
  the S7 click sent the old fingerprint (code 4, "reload the page"). `sendEdit` (app.js) now sends one edit at a time,
  each reading its base after the one before has finished, takes the new fingerprint from the action's result, and
  sends `camera-choose` once more after a conflict (a whole value per shot).
- **Suggesting again failed on a film that names no style** ("pass --style or --set"): a Camera note's revise runs
  `camera suggest --shots … --keep-others` without a source; it now reuses the options' recorded source
  (`set:charisma-ref`). Test: `test_suggest_again_uses_the_recorded_library`.

Not run: the real "Send notes to Claude" job (a Claude run on the owner's account); its steps were run by hand above.
